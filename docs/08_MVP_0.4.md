# EXEL HELL — MVP 0.4

Goal: freeze the graybox core after the first real playtest loop, without adding a new player verb.

## Player actions

- `SORT` — gather data around a RecordKey / FieldKey.
- `CUT` / `PASTE` — move one token through the clipboard.
- `SUM` — requires at least 2 numeric cells.
- `DELETE` — destroy one worksheet cell / quarantine one Corrupted cell.
- `SUBMIT` — checks report cells by final numeric value only.

## SUM rule

Two target modes:

1. **Worksheet target**
   - creates one AggregateToken;
   - consumes the selected sources;
   - remains irreversible compression.

2. **Report Cell target**
   - writes the calculated AggregateToken into the report;
   - does **not** consume the selected sources.

This is the MVP 0.4 solution for overlapping report goals without introducing REF/COPY/manual numeric entry.

## SORT semantic-gap rule

`SORT` follows the worksheet schema, not only the surviving physical tokens.

- Field SORT always reserves one slot per record.
- Record SORT always reserves one slot per field.
- If a value was CUT, consumed, deleted or destroyed, its semantic position remains an empty slot instead of collapsing the rest of the group.

This keeps identity separate from current physical presence.

## #REF!

Continuous-outbreak model:
- first outbreak delay: 3 turns;
- respawn after extinction: 2 turns;
- parallel outbreak delay while active: 3 turns;
- Corrupted lifetime before Destroyed: 2 turns;
- one movement intent per resolution cycle.

Spawn selection uses live report-critical data as anchors.

### Protected report interface

The report header and active Report Cells are interface structure, not destructible worksheet space.

- `#REF!` cannot spawn in them;
- `#REF!` movement cannot target them;
- stale movement intents are rejected if they point at them;
- `DELETE` cannot destroy them and does not spend a turn when attempted;
- answers written into Report Cells remain player-managed values and can still be moved with normal data operations where those operations allow it.

Free cells below the active report area are still ordinary worksheet space.

## Graybox UI fixes

- title displays **MVP 0.4**;
- Report Cells are visually marked in green;
- selected Corrupted / Destroyed cells receive a clear selection outline;
- active #REF! movement and future outbreak telegraphs can be visible simultaneously;
- optional spawn-debug log remains enabled by config.

## Deliberately not changed

- global anomaly cadence;
- #REF! movement AI priorities;
- numeric-only report validation;
- no REF/COPY/manual-number action;
- no new player verbs.

## Stabilization gate

Before moving to LevelConfig/content production, run one short regression pass:

1. future-spawn telegraph stays on one cell until resolved;
2. active movement + future spawn telegraphs are both visible when both exist;
3. Corrupted report/data values are inaccessible and cannot pass SUBMIT;
4. `CUT middle value -> SORT` preserves an empty semantic slot;
5. report header/targets cannot be spawned into, spread into or deleted.

After this regression, MVP 0.4 core rules are frozen except for blocker bugs.
