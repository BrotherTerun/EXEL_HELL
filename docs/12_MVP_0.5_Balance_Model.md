# EXEL HELL — MVP 0.5 multidimensional balance model

Status: authoring/smoke-test model for the `experiment/formula-cells` branch.

The old first-order model `H = spawn delay + preferred distance`, `M = H - C` was useful as a smoke-test filter, but it collapses too much information into one distance number. Formula cells add new spatial infrastructure and new failure modes, so MVP 0.5 needs a model that separates puzzle workload from anomaly pressure.

The model below is not an exact solver. It is an authoring model: every planned level should be measurable before implementation, then corrected from playtest data.

## 1. Core quantities

For a level `L`:

### `C0` — legal base action cost

Minimum number of turn-spending actions required to satisfy all report goals with `#REF!` disabled.

Selection is free. Costs come from the recalculated action sequences in `04_Typical_Action_Sequences.md`.

Examples:
- direct `range -> =SUM()` = 1;
- `key -> =SORT() -> range -> =SUM()` = 2;
- spill relocation + SORT + SUM = 4;
- subtotal A + subtotal B + final SUM = 3.

`C0` must be based on an explicit legal sequence, not only a sum of heuristic solo costs.

If destructive SUM makes the requested goal set impossible without copying a raw token or otherwise violating the current rules, set:

`C0 = ∞`

and reject/redesign the level before tuning anomaly parameters.

### `B` — turn budget

Maximum allowed player actions.

### `R = B - C0` — recovery reserve

How many extra actions the player may spend on anomaly response, bad geometry, or suboptimal ordering before the deadline becomes impossible.

Suggested authoring bands:
- `R >= 6` — generous;
- `R = 4..5` — normal;
- `R = 2..3` — tight;
- `R <= 1` — brittle unless intended as a late challenge.

## 2. Critical entities and lifetime

The important unit is no longer only a raw token. Formula cells create several kinds of critical entities.

Let `E` be the set of entities whose loss can invalidate the chosen optimal plan:

- raw data token;
- key token;
- intermediate aggregate token;
- occupied formula field containing important data;
- empty formula coordinate that must still be used later;
- mandatory spill-lane field.

For every critical entity `e` record:

### `U_e` — last required action index

Last point in the base plan at which `e` must still exist/be usable.

Example: if Salary raw tokens are consumed by action 2 and never needed afterwards, `U_salary = 2`.

An empty final `=SUM()` required only at action 7 has `U_formula = 7` even though it contains no important token before then.

This is the first major correction over the MVP 0.4 distance-only approximation: **empty infrastructure can be temporally critical even before it holds data.**

## 3. Threat arrival estimate

For each entity `e`, estimate the earliest plausible anomaly contact action:

`T_e = F + P_e`

where:

- `F` = first outbreak delay in player actions;
- `P_e` = estimated path/contact time from the chosen outbreak candidate to `e` under current movement rules.

`P_e` is not always equal to Manhattan distance. Use:

`P_e = D_e + G_e`

- `D_e` = minimum Manhattan distance from plausible outbreak candidates to the entity/field;
- `G_e` = geometry penalty/bonus from blocked routes, destroyed cells, corridors, or alternative adjacent routes.

For graybox authoring, use `G_e = 0` unless the layout clearly channels or blocks movement. Correct it after playtest.

### Direct outbreak exposure

Empty formula cells are not important-token anchors, but they may themselves be selected as outbreak cells if they are ordinary valid spawn candidates.

For each critical empty formula/spill field record:

`O_e = 1` if it is eligible for direct outbreak before use, otherwise `0`.

This is separate from `T_e` because direct spawn can bypass route distance.

## 4. Slack

For each critical entity:

`S_e = T_e - U_e`

Interpretation:
- `S_e >= 3` — comfortable;
- `S_e = 1..2` — visible but usually manageable;
- `S_e = 0` — contact at the decision boundary;
- `S_e = -1..-2` — meaningful forced pressure;
- `S_e <= -3` — likely mandatory response/replan or overload.

For a level use:

`S_min = min(S_e)`

and

`Q = count(S_e <= 1) / |E|`

`Q` is the **critical exposure ratio**: the fraction of plan-critical entities under near-term anomaly pressure.

Suggested bands:
- `Q < 0.20` — low exposure;
- `0.20..0.40` — light;
- `0.40..0.65` — strong;
- `> 0.65` — broad systemic pressure.

## 5. Formula infrastructure pressure

Formula cells make spatial infrastructure a finite resource.

### `F_need`

Number of distinct formula activations required by the legal base sequence.

### `F_slots`

Number of useful authored formula coordinates available for those activations, accounting for type (`SUM`/`SORT`) and direction.

### `F_reuse`

Minimum number of occupied formula cells that must be cleared and reused in the legal base sequence.

### Formula Load

`FL = F_reuse / max(1, F_need)`

Interpretation:
- `0` — no formula reuse tax;
- `0..0.25` — light reuse;
- `0.25..0.50` — meaningful infrastructure planning;
- `>0.50` — formula scarcity dominates the puzzle.

Formula reuse actions must already be included in `C0`; `FL` describes *why* the sequence is difficult rather than adding cost twice.

## 6. Spill geometry pressure

For every required SORT `j` define:

- `L_j` = required spill length;
- `Free_j` = number of usable cells in the fixed authored spill lane at level start;
- `Block_j` = minimum number of obstructing tokens/invalid fields that must be moved/removed before execution.

Per-SORT spill pressure:

`SP_j = Block_j / max(1, L_j)`

Level spill pressure:

`SP = mean(SP_j)`

A fully open 5-cell lane has `SP = 0`. One required relocation in a 5-cell lane gives `0.20`.

If a required lane is impossible to clear within the rules, the level is invalid rather than merely difficult.

## 7. Data dependency / goal interference

For every goal `g`, let `S_g` be the set of raw source token IDs required by its legal solution.

For each pair of goals `(a,b)`:

`J_ab = |S_a ∩ S_b| / |S_a ∪ S_b|`

This Jaccard overlap only measures shared data, not whether the overlap is helpful or harmful.

Classify the pair:

- `independent`: `J_ab = 0`;
- `shared-prep`: overlap allows one SORT/subtotal to serve both;
- `ordered`: destructive SUM requires one goal/subtotal before the other;
- `hard-conflict`: no legal sequence preserves the necessary information.

Define:

`DI = mean(J_ab)` over all goal pairs.

and

`OC` = number of mandatory ordering constraints between goals/subtotals.

High `DI` with low `OC` often means efficient shared preparation. High `DI` with high `OC` means the player must reason about dependency order.

Hard-conflict rejects the level regardless of score.

## 8. Workspace pressure

CUT/PASTE requires ordinary safe staging cells.

Let:
- `W_free` = initially usable non-formula, non-report, normal empty fields outside mandatory spill lanes;
- `W_need` = maximum number of simultaneously required staging cells in the base sequence;

`WP = W_need / max(1, W_free)`

Suggested interpretation:
- `<0.15` — spacious;
- `0.15..0.30` — normal;
- `0.30..0.50` — constrained;
- `>0.50` — staging scarcity may dominate.

## 9. Anomaly cadence pressure

Distance alone ignores how many anomaly cycles occur before the plan finishes.

Let:
- `F` = first outbreak delay;
- `A` = active-outbreak parallel delay;
- `Resp` = respawn delay after extinction;
- `C0` = base cost.

Approximate number of anomaly opportunities during an optimal solution:

`N_A = 0`, if `C0 < F`.

Otherwise:

`N_A = 1 + floor((C0 - F) / max(1, A))`

This approximates first outbreak plus possible parallel outbreak windows while the player is still solving.

A quarantine/extinction line can instead interact with `Resp`; use playtest to correct the estimate.

Normalize:

`AP = min(1, N_A / 3)`

So 0 opportunities = 0, one = 0.33, two = 0.67, three or more = 1.

## 10. Loss severity

Not every threatened entity costs the same to lose.

For each critical entity estimate:

`K_e` = minimum extra actions required to recover/reconstruct the plan after losing `e`.

Examples:
- raw value with no duplicate and no way to reconstruct: `K_e = ∞`;
- intermediate subtotal reproducible by one SUM after data remain available: `K_e = 1`;
- occupied SUM aggregate that requires two earlier SORT/SUM actions to reconstruct: `K_e = 2+`;
- only available required formula coordinate destroyed: `K_e = ∞` under current rules.

For finite values normalize:

`KS = mean(min(K_e, 4) / 4)`

For any `K_e = ∞` with `S_e <= 1`, mark the level **catastrophic-exposure candidate**; this is allowed only deliberately and should not be an early tutorial level.

## 11. Two primary indices

### Puzzle Load `PL`

Measures difficulty even with `#REF!` disabled.

Normalize base cost:

`C_n = min(1, C0 / 12)`

Then:

`PL = 100 * (0.45*C_n + 0.20*FL + 0.15*SP + 0.10*DI + 0.10*WP)`

Interpretation (initial authoring bands):
- `0..25` — tutorial/light;
- `26..45` — normal;
- `46..65` — involved;
- `66+` — high cognitive/spatial load.

### Anomaly Threat `AT`

Normalize minimum slack:

`SN = clamp((2 - S_min) / 5, 0, 1)`

This maps comfortable `S_min >= 2` toward 0 and strong negative slack toward 1.

Direct-spawn exposure ratio:

`OR = count(O_e = 1) / |E|`

Then:

`AT = 100 * (0.30*SN + 0.25*Q + 0.15*AP + 0.15*KS + 0.15*OR)`

Interpretation:
- `0..20` — anomaly mostly decorative;
- `21..40` — light pressure;
- `41..60` — active tactical pressure;
- `61..80` — severe;
- `81+` — likely chaotic/catastrophic.

## 12. Combined level score

Use only after checking legal solvability and catastrophic exposure.

`D = 0.55*PL + 0.45*AT`

The weighting intentionally keeps base puzzle complexity slightly more important than anomaly aggression.

Do not compare levels only by `D`. Keep the pair `(PL, AT)` visible.

Two levels can both score 45 while being very different:
- `PL 60 / AT 27`: hard puzzle, mild anomaly;
- `PL 30 / AT 63`: simple calculation under heavy threat.

That distinction is useful for pacing.

## 13. Required authoring sheet per level

Every planned MVP 0.5 level document should list:

1. board size and turn budget;
2. exact starting grid;
3. report goals;
4. authored SUM/SORT coordinates and SORT direction;
5. explicit minimum legal action sequence;
6. `C0`, `B`, `R`;
7. critical entities with `U_e`, estimated `T_e`, `S_e`, direct-outbreak eligibility and `K_e`;
8. `FL`, `SP`, `DI`, `OC`, `WP`, `N_A/AP`;
9. resulting `PL`, `AT`, `D`;
10. intended playtest question.

Use the first set of authored levels to cover different quadrants rather than only increasing one number.

| Level role | Target PL | Target AT | Purpose |
|---|---:|---:|---|
