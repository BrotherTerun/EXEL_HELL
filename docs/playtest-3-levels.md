# EXEL HELL — внешний плейтест: 3 уровня

Цель билда: дать новому игроку один непрерывный проход из трёх уровней без ручной смены Config в Inspector.

## Состав

1. **Обычный отчёт** — Salary Total + Overtime Total. 10 ходов. `#REF!` отключён: уровень проверяет обучение базовым операциям без тактической угрозы.
2. **Срочная сверка** — Salary Total + Bonuses >= 5. 13 ходов. `#REF!` включён после безопасного старта.
3. **Несходящиеся данные** — Salary of max overtime + Salaries where Hours < 40. 18 ходов. `#REF!` приходит раньше; уровень проверяет semantic-задачи и перестройку таблицы.

После принятого отчёта появляется `NEXT LEVEL`. После третьего уровня — `PLAYTEST COMPLETE`. `RESET` перезапускает текущий уровень.

Ожидаемые ответы скрыты в build-конфигурации. Spawn debug также выключен.

## Сборка

В Build Settings уже включена единственная runtime-сцена `Assets/Scenes/SampleScene.unity`. Для Windows достаточно обычного `File -> Build Profiles/Build Settings -> Windows -> Build`.

Рекомендуемый формат распространения: папка Windows build целиком в ZIP. Не передавать тестировщику таблицу ожидаемых ответов или smoke-test документы.

## Что спросить после прохождения

- Где он впервые понял, что нужно делать с таблицей?
- Какие операции он использовал и какие проигнорировал?
- Где впервые пришлось менять первоначальный план из-за `#REF!`?
- Было ли понятно, почему конкретные данные принадлежат конкретному сотруднику/полю после SORT/CUT/PASTE?
- На каком уровне стало скучно, непонятно или слишком напряжённо?
- Сколько попыток потребовал каждый уровень?

Не объяснять механику сверх того, что видно в самом UI, пока игрок явно не застрял из-за интерфейсной непонятности.
