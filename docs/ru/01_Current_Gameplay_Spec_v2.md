# EXEL HELL — актуальная спецификация геймплея v2

**Статус: АКТУАЛЬНО / ядро FC2 заморожено.**  
После этой точки изменения ядра допускаются только для блокирующих ошибок.

## 1. Экономика ходов

### Бесплатно
- клик/выбор одной ячейки;
- прямоугольное выделение `Shift + Drag`;
- изменение/сброс выделения;
- наведение/чтение данных и строки формул;
- недопустимый сброс/действие;
- проверка `SUBMIT`.

### Успешно стоит 1 ход
- MOVE одного перемещаемого токена;
- MOVE выделенного набора токенов как одного прямоугольного переноса;
- MOVE свойства пустой FormulaCell;
- сброс FieldKey/RecordKey в пустую `=SORT()`;
- сброс корректного выделенного числового диапазона в пустую `=SUM()`;
- DELETE/карантин.

После успешного действия аномалия разрешается один раз.

## 2. Грамматика ввода

`Drag = MOVE`  
`Shift+Drag = SELECT RANGE`

Ctrl/несвязного выделения нет. Выделение — один непрерывный прямоугольник.

Строка формул только для чтения и генерируется автоматически. Вводить формулы нельзя.

## 3. Слои ячейки

Одна координата листа может одновременно содержать независимые свойства:

1. **Свойство Report** — постоянная авторская инфраструктура отчёта.
2. **Свойство Formula** — none / SUM / SORT; можно перемещать, когда пусто.
3. **Токен-содержимое** — Data, FieldKey, RecordKey, Aggregate или Label.
4. **Состояние аномалии** — Normal / Corrupted / Destroyed.

При перетаскивании из формульной ячейки действует приоритет:

`сначала содержимое → свойство формулы только если ячейка пуста`

Свойство Report не перемещается вместе с формулой/содержимым.

## 4. MOVE

### Один токен

Перетащить перемещаемое содержимое в допустимую цель. Расстояние/путь дополнительного хода не требуют; важна только допустимость конечной позиции.

Обычная ReportCell является допустимой целью, если пуста.

### MOVE диапазона

После `Shift+Drag` перетаскивание занятой перемещаемой ячейки внутри многоячеечного выделения переносит всё выбранное перемещаемое содержимое одним действием.

Правила:
- относительные позиции сохраняются;
- обычные пустые исходные ячейки не входят в полезную нагрузку;
- перемещаемые токены могут перекрывать собственный переносимый исходный след;
- целевые координаты должны находиться на поле, быть Normal, не иметь Formula для размещения токена и не содержать чужого содержимого;
- успешный MOVE диапазона очищает выделение.

Перетаскивание ячейки вне текущего выделения переносит только верхний слой источника.

### MOVE формулы

**Пустую** FormulaCell можно перетащить в другую допустимую пустую координату, включая пустую ReportCell.

Если FormulaCell содержит объект, первое перетаскивание переносит объект и оставляет свойство формулы на месте. Только после этого можно переместить формулу.

Общий жизненный цикл SUM и SORT:

`пустая формула → сброс входа → занятая формула → MOVE содержимого наружу → пустая формула → MOVE формулы`

## 5. SUM

Активация только через DROP:

`выделенный числовой прямоугольник → drag/drop → пустая =SUM()`

Требования:
- минимум два числовых операнда;
- операнды — токены Data или Aggregate;
- исходные ячейки должны быть Normal;
- обычные пустые Normal-ячейки внутри прямоугольника разрешены и игнорируются;
- ключи/метки делают диапазон недопустимым;
- целевая формула не может находиться внутри собственного исходного выделения;
- формула-цель должна быть пустой/доступной.

Разрешение:
1. вычислить сумму;
2. записать происхождение/ID источников;
3. обычные числовые источники разрушительно поглощаются;
4. числовое содержимое ReportCell — **постоянный операнд**: читается, но не поглощается;
5. итоговый Aggregate становится содержимым SUM FormulaCell;
6. строка формул может показать сгенерированное `=SUM(A1:B3)`;
7. потратить одно действие.

## 6. SORT

Активация только через DROP:

`один FieldKey/RecordKey → drag/drop → пустая =SORT()`

Правила:
- направление spill для FieldKey = **вниз**;
- для RecordKey = **вправо**;
- запасного направления нет;
- учитываются полные семантические позиции схемы;
- spill должен помещаться в допустимые Normal/не-Formula ячейки;
- токены, уже входящие в перенос, могут перекрывать собственные исходные позиции;
- чужое содержимое блокирует spill;
- недопустимый spill не тратит действие;
- ключ становится содержимым SORT FormulaCell;
- связанные Data-токены перемещаются в позиции spill;
- строка формул может показать сгенерированное `=SORT(sourceAddress)`;
- потратить одно действие.

Чтобы повторно использовать ту же SORT, сначала вынесите из неё ключ через MOVE.

## 7. Цели отчёта и ReportCell

Свойство Report — защищённая инфраструктура. Целевая ячейка может также содержать свойство Formula.

Есть три режима авторинга:

### DirectValue
Пример: `SalaryOfMaxOvertime`.

Цель — **обычная ReportCell**. Требуемый Data-токен перемещается прямо туда.

Формула на DirectValue-цели считается подозрительной и вызывает предупреждение валидации.

### Aggregate / InlineSUM
Целевая ReportCell также содержит `=SUM()`.

Выбранные операнды сбрасываются прямо в формулу отчёта. Результат вычисляется и сохраняется там за одно формульное действие.

### Aggregate / PlainDelivery
Цель — **обычная ReportCell без формулы**.

Агрегат вычисляется в другом месте и затем через MOVE доставляется в целевую ячейку. Это намеренно допустимый вариант: дизайн уровня может уменьшить запас формул и проверить, создают ли общие/рабочие формулы реальные пространственные решения.

Это правило заменило прежнее предупреждение, согласно которому каждая агрегатная цель отчёта обязана сама быть `=SUM()`.

Агрегатная цель отчёта не должна содержать `=SORT()`.

## 8. Постоянство отчёта

Числовое содержимое ReportCell можно выбирать как операнд последующей SUM без его поглощения.

Так можно удовлетворить цель A, затем использовать зафиксированное значение как часть цели B.

Постоянство является свойством **ReportCell**, а не особым режимом SUM.

## 9. DELETE

DELETE допустимой ячейки листа стоит одно действие.

Применение:
- пожертвовать обычной ячейкой/данными;
- изолировать Corrupted-ячейку.

Заголовок отчёта и активные ReportCell защищены. Попытка DELETE для них недопустима и не тратит ход.

Защита свойства Formula следует правилам реализации FC2; DELETE не является универсальным инструментом удаления формул.

## 10. Аномалия #REF!

`#REF!` — постоянный телеграфируемый процесс.

Конфигурация уровня задаёт:
- `FirstOutbreakTurn`;
- `RespawnDelayTurns`;
- `ActiveOutbreakDelayTurns`;
- `CorruptionStepsBeforeDestroy`;
- `SpawnPreferredDistance`;
- `SpawnDistanceVariation`;
- `SpawnCandidatePoolSize`.

Позиции очага выбираются динамически на текущем поле около критичных для отчёта данных. Авторы не расставляют точки спавна вручную.

### Телеграфия
- будущий очаг = полупрозрачная янтарная заливка + яркая рамка;
- намерение активного распространения = полупрозрачная красная заливка без рамки;
- оба сигнала могут существовать одновременно;
- если оба указывают в одну цель, визуал будущего спавна имеет приоритет;
- оверлеи не перехватывают raycast и находятся выше представления FormulaCell.

### Разрешение
Успешное действие игрока продвигает ожидающий очаг/распространение/коррупцию. Выделение и недопустимые действия — нет.

Интерфейс отчёта не может быть целью очага/распространения.

## 11. Победа / поражение

Победа:
- все авторские Report Goals удовлетворены содержимым целевых ячеек;
- игрок отправляет отчёт.

Текущий SUBMIT прежде всего проверяет требуемое итоговое значение/семантику токена, заданную целью. Происхождение результата существует, но не является условием победы.

Поражение:
- текущий дедлайн/лимит ходов истекает до успешной отправки;
- отдельные состояния поля могут стать практически или математически невосстановимыми ещё до формального дедлайна.

Финальная подача отображает лимит ходов как `09:00–18:00`; механику времени это не меняет.

## 12. Совместимость интерфейса формульных уровней

На уровнях FC2 старый рабочий процесс панели SUM/SORT/CUT/PASTE/буфера обмена не является игровой грамматикой. Устаревшие элементы и обучение скрываются/отключаются слоями совместимости.

Остаются:
- DELETE;
- SUBMIT;
- RESET;
- строка формул;
- информация таблицы/отчёта/статуса до окончательной замены подачей финального интерфейса.

## 13. Инварианты ядра

Не менять без повторного открытия дизайна ядра:

- пошаговая детерминированная экономика действий;
- Drag=MOVE / Shift+Drag=SELECT;
- активация формулы только через DROP;
- мобильность пустой формулы;
- занятая формула сначала отдаёт содержимое;
- фиксированные направления SORT;
- разрушительное поглощение обычных источников SUM;
- постоянные числовые операнды ReportCell;
- агрегатная цель отчёта может быть inline-SUM или plain delivery;
- телеграфируемый `#REF!`;
- никакого настоящего парсера Excel / ручного ввода формул.
