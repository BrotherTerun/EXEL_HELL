# EXEL HELL — типовые последовательности действий v2 / FC2

**Статус: АКТУАЛЬНЫЙ справочник по экономике действий.**

Считаются только успешные действия, расходующие ход.

## Бесплатные взаимодействия
- клик/выбор;
- прямоугольное выделение `Shift+Drag`;
- изменение выделения;
- чтение/наведение/строка формул;
- проверка SUBMIT;
- недопустимый DROP.

## Примитивы стоимостью 1 действие
- MOVE токена;
- MOVE выделенного диапазона;
- MOVE пустой FormulaCell;
- key → пустая SORT;
- числовое выделение → пустая SUM;
- DELETE/карантин.

## Основные последовательности

| Последовательность | Стоимость | Примечание |
|---|---:|---|
| Перемещение одного токена | 1 | `token → destination` |
| Перемещение диапазона | 1 | любое число выбранных токенов с сохранением взаимных смещений |
| Data/direct-value goal → ReportCell | 1 | например найденная зарплата → прямая цель отчёта |
| Прямой aggregate в report-SUM | 1 | после подготовки корректного выделения |
| Workspace SUM → обычная aggregate ReportCell | 2 | SUM + MOVE агрегата в отчёт |
| FieldKey/RecordKey → SORT | 1 | требуется полностью допустимый spill |
| SORT + inline report SUM | 2 | после подготовки ключа/данных |
| SORT + workspace SUM + plain delivery | 3 | типичный вариант с дефицитом SUM |
| Сначала переместить пустую формулу | +1 | оправдано, если позиция меняет геометрию/угрозу |
| Убрать один блокер + SORT + SUM | 3 | MOVE блокера + две формулы |
| Карантин + SORT + SUM | 3 | DELETE + две формулы |
| Эвакуировать критичный токен + SORT + SUM | 3 | защитный MOVE + две формулы |
| Извлечь результат занятой SUM | +1 | если сразу доставлен в ReportCell — полезная доставка, а не чистый налог |
| Извлечь ключ занятой SORT | +1 | парковка только ради освобождения формулы — handling tax |
| Повторно использовать одну SORT для двух ключей | 3 до вычислений | SORT A → MOVE key A → SORT B |

## Режимы целей отчёта

### DirectValue
Формула в цели не нужна. Доставить правильный Data-токен.

### InlineSUM
ReportCell содержит SUM. После подготовки агрегация стоит 1 действие; результат остаётся внутри формулы, пока содержимое не вынесено.

### PlainDelivery
Aggregate-цель не содержит формулы. Посчитать в другом месте и MOVE-нуть результат в ReportCell.

Обычно это на одно действие дороже InlineSUM, но доставка одновременно освобождает рабочую SUM. Поэтому при дефиците формул это может быть осмысленным переиспользованием, а не чистым налогом.

При сравнении запасов формул такой MOVE считать `F_delivery`, а не `F_tax`.

## Примеры нескольких целей после подготовки

### Две независимые aggregate-цели

Две выделенные report-SUM:

`range A → report SUM A → range B → report SUM B` = **2 вычислительных действия**.

Одна переиспользуемая workspace-SUM + две plain report-цели:

`range A → SUM → MOVE aggregate A → range B → SUM → MOVE aggregate B` = **4 действия**.

Дополнительные +2 оправданы только если общая формула создаёт настоящее решение о размещении/угрозе/порядке.

### Одна workspace-SUM, одна inline-цель

В зависимости от порядка смешанная схема может требовать 3 действия на две агрегации: одна inline SUM и одна workspace SUM + delivery. Это полезная промежуточная точка для экспериментов с дефицитом формул.

### Две SORT-зависимые aggregate-цели

При достаточной инфраструктуре (`2 SORT + 2 inline report-SUM`) после фильтрации нужны четыре полезные активации:

`SORT A → SUM A → SORT B → SUM B`.

Одна общая SORT добавляет извлечение между активациями. Хорошо ли это — зависит от того, можно ли извлечённый ключ сразу использовать осмысленно.

## Текущие семантические нижние границы

Это **нижние границы**, а не готовые уровни. Геометрия, фильтрация, запас формул и аномалия могут повышать законный `C0`.

| Цель | `C_sem` | Обоснование |
|---|---:|---|
| `SalaryTotal` | 2 | SORT Salary + SUM |
| `OvertimeTotal` | 2 | SORT Overtime + SUM |
| `BonusTotal` | 2 | SORT Bonus + SUM |
| `BonusAtLeastFour`* | 4 | SORT Bonus + два filter MOVE + SUM |
| `SalaryOfMaxOvertime` | 3 | SORT Overtime + SORT Salary + direct MOVE |
| `SalaryForHoursBelowForty` | 5 | SORT Hours + SORT Salary + два filter MOVE + SUM |
| LowHours + OT Total + Bonus Total | 9 | 4 SORT + 2 filter MOVE + 3 SUM |

`*` Историческое имя enum; текущая реализация использует порог `bonus >= 5`.

## Сравнение дефицита формул

Для варианта уровня:

1. записать `C_sem` при достаточной инфраструктуре;
2. записать точный законный `C0` для авторского запаса/раскладки;
3. посчитать `Δ = (C0 - C_sem) / C_sem`;
4. отделить осмысленные пространственные MOVE от обслуживания формул;
5. посчитать FHL по балансной модели.

Предупреждение авторингу:

> Если дефицит формул повышает `C0` более чем примерно на 35% относительно `C_sem`, но не создаёт хотя бы одного настоящего решения по размещению/порядку/угрозе, это скорее налог на действия, чем глубина.

Обычные aggregate ReportCell — инструмент эксперимента, а не автоматически лучший дизайн.

## Диапазоны сложности по длине полезного маршрута

- **L0: 0** — ответ уже зафиксирован; не пазл.
- **L1: 1–2** — атомарная операция / фрагмент обучения.
- **L2: 3–4** — фильтрация, одно перемещение, одна доставка/защита.
- **L3: 5–7** — несколько проекций, зависимости, осмысленный reorder/reuse.
- **L4: 8+** — позднее многоцелевое столкновение; не использовать как одиночную цель.

Не делать финальный уровень сложнее только увеличением числа действий. Поздняя идентичность должна идти главным образом от психоза/подачи и контролируемой ненадёжности интерфейса.
