# EXEL HELL — Design Tasks

## Назначение
Короткое ТЗ на первый playable prototype.

## T01. Spreadsheet Grid
**Зачем:** создать поле, на котором происходят и работа, и угроза.

**Требования:**
- Размер: 10×10.
- Каждая ячейка хранит: координату, значение, состояние.
- Допустимые состояния: `Normal`, `Corrupted`, `Destroyed`.
- `Destroyed` не хранит игрового значения и не может использоваться формулами.

**Готово, когда:** таблица создаётся, клетки адресуются по координатам, их состояние можно менять из кода.

## T02. Selection
**Зачем:** дать игроку основной способ взаимодействия с таблицей.

**Требования:**
- Клик выбирает одну клетку.
- Drag выбирает прямоугольный диапазон между начальной и конечной клеткой.
- Выделение визуально подсвечивается.
- Код получает список выбранных `Cell`.

**Готово, когда:** можно стабильно выбрать, например, `B2:B6` и получить именно эти клетки.

## T03. Turn Manager
**Зачем:** создать конфликт между работой и распространением ошибки.

**Требования:**
- День имеет ограниченное число ходов. Стартовое значение для теста: 15.
- `SUM`, `CUT`, `PASTE`, `DELETE` тратят по 1 ходу.
- После действия игрока: `Turn++` → ход аномалии → проверка win/lose.
- Если ходы закончились без принятого отчёта — поражение.

**Готово, когда:** каждое валидное действие стабильно запускает один ответный ход таблицы.

## T04. SUM
**Зачем:** основной рабочий инструмент для выполнения отчёта.

**Требования:**
- Работает только по выбранным числовым `Normal` клеткам.
- Вычисляет сумму значений диапазона.
- После выбора целевой клетки записывает туда результат.
- Не уничтожает исходные клетки в первом прототипе.
- Тратит 1 ход после успешного применения.

**Готово, когда:** игрок может вычислить один из показателей отчёта через `SUM`.

## T05. Clipboard: CUT / PASTE
**Зачем:** дать игроку средство эвакуации важных данных.

**Требования:**
- Clipboard хранит максимум одно значение.
- `CUT`: значение выбранной `Normal` клетки → Clipboard; исходная клетка очищается.
- `PASTE`: значение Clipboard → выбранная доступная клетка; Clipboard очищается.
- `CUT` и `PASTE` тратят отдельные ходы.
- Нельзя вырезать `Corrupted` или `Destroyed` клетку.

**Готово, когда:** значение можно спасти из опасной зоны ценой двух ходов.

## T06. DELETE
**Зачем:** дать игроку грубую контрмеру против заражения.

**Требования:**
- Выбранная клетка переводится в `Destroyed`.
- Содержимое уничтожается.
- `Destroyed` клетка не заражается и не участвует в формулах.
- Тратит 1 ход.

**Готово, когда:** игрок может вручную создать разрыв в пути распространения `#REF!` ценой данных/пространства.

## T07. `#REF!` Anomaly
**Зачем:** главный противник прототипа.

**Требования:**
- На старте уровня имеет заранее заданную позицию и момент активации.
- `Corrupted` клетка отображается как `#REF!`.
- На следующем ходе активная `Corrupted` клетка становится `Destroyed`.
- Перед уничтожением/в рамках хода заражение передаётся одной соседней клетке по 4 направлениям.
- Приоритет цели:
  1. соседняя клетка содержит данные, нужные для отчёта;
  2. соседняя клетка ближе по Manhattan distance к ближайшей нужной клетке;
  3. случайный валидный сосед.
- `Destroyed` клетки блокируют распространение.

**Готово, когда:** ошибка предсказуемо угрожает полезным данным и игрок может менять её маршрут своими действиями.

## T08. Report Goals
**Зачем:** игрок должен не просто выживать, а выполнять работу.

**Требования:**
- На уровне 3 обязательных показателя.
- У каждого: название, правильное значение, целевая клетка.
- Целевые значения вычислимы из стартовых данных.
- UI показывает список показателей и их текущие значения.

**Готово, когда:** все три показателя можно получить штатными инструментами прототипа.

## T09. SUBMIT REPORT
**Зачем:** дать игроку явную конечную цель и возможность самому завершить забег.

**Требования:**
- Кнопка доступна в любой момент до дедлайна.
- При нажатии сверяются три целевых значения.
- Все верны → `Win`.
- Есть ошибка → отчёт отклоняется, игра продолжается, если остались ходы.
- Сам `SUBMIT` не тратит ход в первом прототипе.

**Готово, когда:** правильный отчёт завершает игру, неправильный даёт понятный feedback.

## T10. Lose Conditions
**Зачем:** ограничить пространство решений.

**Требования:**
- `Deadline`: осталось 0 ходов, отчёт не принят.
- `Data Lost`: обязательный показатель больше невозможно вычислить из оставшихся данных.
- Для первого билда допустимо реализовать только `Deadline`, если автоматическая проверка `Data Lost` задерживает core-test.

**Готово, когда:** проигрыш однозначно фиксируется и уровень можно перезапустить.

## T11. Prototype UI
**Зачем:** сделать состояние игры читаемым без polish.

**Минимум на экране:**
- таблица;
- выделение;
- кнопки `SUM`, `CUT`, `PASTE`, `DELETE`;
- Clipboard value;
- список 3 показателей;
- оставшиеся ходы;
- `SUBMIT REPORT`;
- текст Win/Lose.

**Готово, когда:** новый тестировщик понимает текущее состояние без просмотра Inspector.

## T12. Test Level
**Зачем:** проверить наличие решения, а не генератор контента.

**Требования:**
- Один авторский набор данных.
- Первые 2–3 хода позволяют безопасно освоить взаимодействия.
- После этого активируется `#REF!`.
- Хотя бы один показатель требует выбрать между продолжением расчёта и спасением данных.
- Должен существовать минимум один стабильный путь к победе.
- Желательно минимум одно состояние с двумя разумными решениями.

**Критерий успешного core-test:**
Игрок хотя бы один раз осознанно выбирает: **«продвинуть отчёт сейчас или потратить ход на спасение данных»**.

## Стоп-лист до успешного core-test
Не реализовывать:
- новые формулы;
- новые аномалии;
- сюжет/чат начальника;
- полноценный Excel UI;
- звук/VFX;
- меню/settings/save;
- procedural generation.
