## Известные неблокирующие особенности разработки

### Прямой запуск `Gameplay.unity`
Прямой Play сцены — разработческий шорткат, не production boot path.

Текущее поведение намеренно удаляет постоянную оболочку Application, если она была создана с `GameplayActive=false`. Последствия:
- может появиться старый standalone fallback HELP;
- кнопка `MENU` не имеет экземпляра Application и ничего не делает;
- может остаться небольшой bootstrap-flicker.

Нормальный путь релиза `Menu → Gameplay` этих отличий не имеет. Исправлять паритет прямого запуска только если он действительно нужен разработке.

### Косметика экспорта конструктора
Экспортёр пока сериализует комбинированные `ReportGoals` числовыми enum-флагами, например `(PrototypeReportGoals)52`. Это корректный C#, но менее читаемо, чем явное `A | B | C`. Только косметика.

## Явно закрытые / вырезанные направления

Не открывать заново при финализации без блокирующей причины:
- часы реального времени;
- старый toolbar-процесс SUM/SORT;
- обязательный CUT/PASTE внутрь формул;
- фиксированные неперемещаемые FormulaCell;
- настоящий редактор/парсер формул Excel;
- процедурный генератор уровней;
- большой граф/редактор нарратива;
- полноценный ввод в чат/социальный симулятор;
- большой набор правил психоза;
- слияние production обратно в `agent/prototype-core`.

## Определение «текущая сборка готова к наполнению»

Инфраструктура готова к контенту, когда:
- Unity компилируется без блокеров;
- Menu NEW/CONTINUE/LOAD ведут на правильный уровень в Gameplay;
- import/export конструктора работает туда-обратно;
- принятые экспорты уровней закоммичены в `PrototypeLevelCatalog`;
- записаны базовые допустимые маршруты и бюджеты ходов.

На этой точке оставшаяся неопределённость должна быть в **контенте уровней и подаче**, а не в очередном редизайне базовой грамматики взаимодействий.
