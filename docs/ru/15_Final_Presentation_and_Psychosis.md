# EXEL HELL — финальная подача / чат / психоз

**Статус: ЦЕЛЕВОЕ состояние финальной джемовой подачи.**  
Документ описывает состояние после NarrativeLayer и принятых уровней; не каждая подсистема существовала на момент записи.

## 1. Визуальный lock

EXEL HELL — **не** буквальный симулятор Excel/Windows.

Целевая композиция:
1. приглушённый пиксельный офисный фон;
2. стилизованное игровое окно/таблица как главная тактическая поверхность;
3. единая пиксельная оболочка меню/чата/часов/панелей;
4. небольшой анимированный спрайт протагониста как реактивный персонаж интерфейса/сцены.

Таблица остаётся фокусом взаимодействия и обязана сохранять читаемость:
- чисел;
- ключей;
- адресов;
- `=SUM()` / `=SORT()`;
- выделенного диапазона;
- допустимости drag/drop;
- целей отчёта;
- настоящей телеграфии `#REF!`.

Психоз может визуально лгать вокруг этих систем, но не должен делать настоящую тактическую информацию нечитаемой.

## 2. Офисный фон

Обязательный дешёвый слой атмосферы:
- холодный серо-синий офис;
- циклы монитора/лампы/вентиляции/силуэтов;
- минимум сложной анимации NPC;
- постепенная неправильность/коррупция на поздних уровнях.

Офис обрамляет игру и даёт физический контекст герою/чату/подаче, но не превращается в исследуемое пространство.

## 3. Протагонист

Игрок им не управляет.

Небольшой sprite/UI-character примерно с 2–4 авторскими состояниями:
- normal/tired;
- tense;
- scared/alarmed;
- broken/psychotic.

Narrative events могут вызывать выражения/реакции. Не строить ради джема большую skeletal/animation state machine.

## 4. Часы рабочего дня

Видимый счётчик ходов заменяется электронным офисным временем:

`09:00 → 18:00`

Расчёт:

`totalMinutes = 540 + round(540 * currentTurn / maxTurns)`

Правила:
- успешное gameplay-действие двигает время;
- selection/UI inspection/invalid drop — нет;
- Reset начинает с 09:00;
- последний ход = ровно 18:00;
- раннее завершение показывает фактически вычисленное время;
- внутренний turn остаётся каноническим для gameplay/NarrativeLayer triggers.

## 5. Чат

Чат **не открыт постоянно**.

На основном экране есть отдельная кнопка и unread-state.

Полное окно содержит два канала:
- `НАЧАЛЬНИК`;
- `ОТДЕЛ`.

У каждого есть история. Игрок не вводит текст.

Источники сообщений:
- scripted narrative events;
- reactive gameplay events;
- опциональный случайный авторский пул.

## 6. Toast-уведомления

Входящие сообщения создают маленький toast:
- достаточно короткий для чтения без открытия чата;
- не закрывает тактическую область таблицы;
- клик открывает нужный канал/историю;
- unread сохраняется по выбранной политике;
- presentation-click бесплатен.

Примеры начальника:
- `Отчёт должен быть готов до 18:00.`
- `Почему файл ещё открыт?`
- `Не удаляйте строки самостоятельно.`

Примеры отдела:
- `у кого-нибудь тоже формулы сами двигаются?`
- `я перезапустил файл, вроде прошло`
- `ребят у меня в ячейке написано помогите`

Поздние сообщения могут становиться явно невозможными/неправильными.

## 7. Шкала психоза 0–4

Одна глобальная/прогрессионная величина. Не строить десятки несвязанных систем.

### 0 — normal
- обычный офис/таблица;
- максимум мелкие визуальные несовершенства.

### 1 — suspicious
Только presentation:
- лёгкий jitter текста/границ;
- краткий color shift;
- на мгновение неправильный hover;
- странные сообщения в ячейке/у героя/в чате.

### 2 — clearly wrong
Всё ещё в основном presentation:
- ghost cells;
- flicker;
- визуальный offset строки/столбца;
- временно неправильные labels;
- элементы UI на мгновение рассинхронизируются и восстанавливаются.

### 3 — начинается gameplay distortion
Только после ясной телеграфии:
- временно disabled cell;
- реальный row offset;
- реальный column offset;
- опционально временный отказ/шум формулы.

### 4 — final
- несколько контролируемых distortions;
- UI/chat/table визуально конфликтуют;
- офис/герой сильно повреждены;
- настоящая игра остаётся решаемой и читаемой.

## 8. Максимальный набор gameplay-примитивов психоза

Предпочтительно только три:

### `DisableCell(cell, turns)`
Временно недоступная координата с ясной длительностью/телеграфией.

### `ShiftRow(row, delta)`
Контролируемое физическое/семантическое смещение с ясной подачей до/после.

### `ShiftColumn(column, delta)`
То же для столбца.

Если один примитив оказывается дорогим/нечитаемым — релизить с двумя. Presentation может создавать разнообразие без размножения правил.

## 9. Правило дизайна психоза

> Presentation может быть хаотичной. Gameplay-эффекты должны быть маленькими, авторскими/телеграфируемыми и обучаемыми.

Никогда не подделывать настоящую оранжевую/красную телеграфию REF так, чтобы игрок не мог отличить правду. Ложный/шумный сигнал возможен только если настоящая угроза остаётся отдельно читаемой.

## 10. Эскалация по уровням

- L1: psychosis 0, только narrative/tutorial;
- L2: 0→1, первые подозрительные события вокруг REF;
- L3: 1→2, сильные presentation-аномалии, почти без изменения правил;
- L4: 2→3, первое ограниченное gameplay-distortion после телеграфии;
- L5: 3→4, основная идентичность идёт от ненадёжности интерфейса, а не сильно большего `C0`.

Точные narrative-моменты авторить только после стабилизации маршрутов/таймингов уровней.

## 11. Библиотека анимации/presentation

Переиспользуемые helper'ы для:
- hover/select;
- token pick-up / drag ghost;
- valid/invalid drop;
- SUM collapse;
- SORT spill;
- REF spawn/spread/impact;
- corruption/death;
- report accepted;
- toast in/out;
- typewriter message;
- menu/chat transition;
- protagonist reaction;
- glitch manifestation/dismiss.

Предпочтительный существующий presentation-layer — PrimeTween.

## 12. Цель по аудио

Небольшой семантический набор SFX (~12–15 событий) + минимум музыкальных состояний.

Возможная структура:
- normal office loop;
- anxious/drone/distorted layer;
- crossfade/intensity под контролем psychosis.

Лучше два хорошо срежиссированных состояния, чем пять несвязанных треков.

## 13. Ограничители доступности/читаемости

- избегать постоянного тяжёлого CRT/noise поверх данных;
- искажение шрифта не должно делать цифры/формулы неоднозначными;
- report goals остаются узнаваемыми;
- цвет по возможности не является единственным маркером состояния;
- dismiss/notification психоза не тратят игровые действия;
- UI scaling проверить на целевых 16:9/16:10 разрешениях.
