# EXEL HELL — спецификация Formula Cells 2.0 v2

**Статус: РЕАЛИЗОВАНО / ЯДРО ОДОБРЕНО / ЗАМОРОЖЕНО.**  
Это каноническая спецификация FormulaCell. Заменяет первое предложение из `11_MVP_0.5_Formula_Cells_Spec.md`.

## Зачем существует v2

Первое предложение MVP 0.5 использовало фиксированные FormulaCell и взаимодействие `бесплатное выделение → клик/активация`. Плейтесты и реализация показали, что это создаёт недостаточно прямой пространственной манипуляции и рискует ощущаться надуманно.

FC2 поменял грамматику на:

`Drag = MOVE`  
`Shift+Drag = SELECT`  
`Выполнение формулы = DROP внутрь формулы`

Сами свойства формулы стали перемещаемыми, пока ячейка пуста.

## 1. Модель слоёв

Координата ячейки может содержать независимые слои:

`Report property + Formula property + Occupant token + Cell anomaly state`

Свойство Formula:
- none;
- SUM;
- SORT.

Occupant:
- Data;
- FieldKey;
- RecordKey;
- Aggregate;
- Label.

Свойство Report — авторская инфраструктура и остаётся на координате.

Свойство Formula можно перемещать **только когда оно пусто**.

## 2. Универсальный приоритет drag

При перетаскивании формульной координаты:

1. если occupant существует — перетаскивается occupant;
2. formula остаётся;
3. когда formula пуста, drag может переместить само свойство Formula.

Примеры:

`=SUM(247)` → перетащить 247 → источник становится `=SUM()`.

`=SORT(Зарплата)` → перетащить ключ Salary → источник становится `=SORT()`.

Отдельного инструмента перемещения формулы нет.

## 3. Выделение

`Shift+Drag` создаёт одно прямоугольное выделение.

Выделение бесплатно. Оно используется главным образом как набор операндов SUM и как исходная полезная нагрузка для MOVE диапазона.

Ctrl/несвязных выделений нет.

## 4. MOVE диапазона

Перетаскивание занятой перемещаемой ячейки внутри многоячеечного выделения переносит все выбранные перемещаемые token-occupant одним действием.

- относительные позиции сохраняются;
- пустые исходные клетки игнорируются;
- свойства Formula не перемещаются вместе с token payload;
- переносимые occupant могут перекрывать собственный переводимый исходный след;
- чужие occupant / Formula-цели / не-Normal клетки блокируют;
- успешное действие стоит 1 ход.

## 5. FormulaCell SUM

### Пустое состояние
`=SUM()`

### Активация
Выбрать допустимый прямоугольный числовой диапазон, затем перетащить/сбросить выбранную полезную нагрузку в пустую SUM.

Требования:
- минимум 2 числовых операнда;
- только числовые Data/Aggregate;
- пустые Normal-клетки внутри прямоугольника разрешены и игнорируются;
- исходные клетки Normal;
- целевая формула не внутри исходного выделения;
- цель пуста/доступна.

### Результат
- вычисляется сумма;
- сохраняется происхождение;
- обычные исходные числовые токены поглощаются;
- числовые occupant ReportCell являются постоянными операндами и сохраняются;
- Aggregate occupant появляется внутри SUM;
- расходуется одно действие.

### Повторное использование
Вынести Aggregate occupant — SUM останется пригодной к повторному использованию.

Если этот MOVE доставляет aggregate прямо в обычную ReportCell, извлечение и полезная доставка являются одним и тем же действием.

## 6. FormulaCell SORT

### Пустое состояние
`=SORT()`

### Активация
Перетащить один FieldKey/RecordKey в пустую SORT.

### Направление
- FieldKey → вниз;
- RecordKey → вправо;
- запасного направления нет.

### Разрешение
- семантическая группа определяется по схеме;
- все позиции spill должны быть допустимы;
- связанные Data-токены перемещаются в spill;
- ключ становится occupant SORT;
- недопустимый spill не тратит ход;
- успешный SORT стоит 1 действие.

### Повторное использование
Сначала вынести key occupant. Парковка ключа только ради освобождения SORT — налог обслуживания формулы; перемещение в полезную позицию может им не быть.

## 7. Перемещение формулы

Пустую FormulaCell можно переместить в допустимую пустую координату, включая пустую ReportCell.

Это стоит одно действие.

Мобильность формулы не является автоматически хорошим дизайном. Полезный перенос должен менять хотя бы одно из:
- возможность spill;
- геометрию/постановку результата SUM;
- подверженность аномалии;
- будущий маршрут/порядок;
- эффективность действий относительно расчистки блокеров.

Формула с единственной осмысленной позицией часто является просто фиксированной формулой плюс налог MOVE.

## 8. Сочетание Report + Formula

Свойства Report и Formula независимы.

### Aggregate goal / InlineSUM
Report target также содержит SUM. Вычисление происходит прямо в ней.

### Aggregate goal / PlainDelivery
Report target не содержит формулы. Aggregate считается в другом месте и MOVE-ится в цель.

Это валидно и намеренно поддерживается для проверки уменьшенного запаса/повторного использования формул.

### DirectValue goal
Цель должна быть обычной ReportCell. Требуемый Data-токен перемещается туда.

### Недопустимые/подозрительные случаи
- aggregate Report target с SORT → предупреждение;
- direct-value Report target с любой Formula → предупреждение.

## 9. Постоянные Report-операнды

Любой числовой occupant ReportCell является постоянным операндом последующей SUM:
- его можно включить в выбранный диапазон;
- значение участвует в сумме;
- occupant не поглощается.

Это поддерживает упорядоченные/опосредованные отчётом зависимости целей без COPY.

Постоянство — свойство ReportCell, а не специальное правило report-SUM.

## 10. Строка формул

Только для чтения / генерируется автоматически.

Примеры:
- `=SORT(B1)`;
- `=SUM(B3:B7)`.

Игрок не может вводить, редактировать или создавать формулы через неё.

## 11. Взаимодействие Formula / REF

Формульные координаты не являются постоянными безопасными хранилищами.

Угроза `#REF!` определяется правилами поля/аномалии и текущими важными occupant/геометрией. Телеграфия должна оставаться читаемой.

Текущий слой телеграфии рисуется поверх полного представления FormulaCell:
- spawn — янтарный полупрозрачный + рамка;
- spread — красный полупрозрачный;
- raycast не перехватывается.

## 12. Совместимость старой панели инструментов

Формульные уровни не используют старую грамматику toolbar SUM/SORT/CUT/PASTE. Слой совместимости скрывает устаревшие кнопки и предположения обучения.

DELETE/SUBMIT/RESET остаются до замены финальным UI.

## 13. Приёмка экономики действий

Обязательные инварианты:
- бесплатное выделение;
- single/range MOVE = 1;
- formula MOVE = 1;
- SORT = 1;
- SUM = 1;
- invalid = 0;
- DELETE = 1.

Простые задачи отчёта не должны раздуваться только из-за существования формул.

Пример при достаточной инфраструктуре:

`SORT Salary → SUM Salary` = 2 действия.

Вариант с обычной ReportCell может стоить 3 (`SORT → workspace SUM → delivery`), потому что сознательно меняет выделенную report-SUM на переиспользуемую инфраструктуру.

## 14. Замороженные не-цели

FC2 не добавляет:
- ввод/редактирование формул;
- постоянные объекты A1-ссылок;
- семантику COPY формул;
- цепочки автоматического пересчёта;
- динамическое направление SORT;
- новые функции таблицы;
- ручное действие REF;
- произвольное создание формул игроком.

## 15. Ограничитель авторинга

Дефицит формул — переменная дизайна уровня, а не цель сама по себе.

Сравнивать дефицитный вариант с достаточной инфраструктурой по:
- `C_sem`;
- точному законному `C0`;
- `FHL`;
- альтернативам размещения;
- запасу восстановления под REF.

Если дефицит добавляет >~35% стоимости действий без осмысленного решения о размещении/порядке/угрозе, увеличить запас формул или переделать уровень.
