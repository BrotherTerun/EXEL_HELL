# Final UI Shell — контракт production-компоновки

## Объём

Этот слой заменяет композицию prototype-экрана, не меняя правила пазла. Существующие callbacks листа/формул/кнопок сохраняются; поверх них добавляются только presentation-runtime adapters.

Опорное разрешение: **1600×900**, `ScaleWithScreenSize`, width/height match = `0.5`.

## Композиция

Production-экран трактуется как стилизованное игровое окно, а не клон Excel/Windows.

- внешнее игровое окно размещено внутри presentation-stage 1600×900;
- worksheet — основная левая область;
- formula bar — непосредственно над worksheet;
- правый rail — область отчёта/задач/контролов;
- слот протагониста — верхняя правая presentation-область;
- часы рабочего дня — справа сверху, отдельно от механики ходов;
- Messages — компактная кнопка/область уведомления;
- transient toast layer — поверх UI игрового окна;
- footer/status reserve — нижняя полоса для позднего art/status оформления.

Пиксельный офис и финальные шрифты/спрайты намеренно отложены до visual pass. Здесь сначала фиксируются геометрия и точки взаимодействия.

## Часы рабочего дня

Gameplay по-прежнему считает целые ходы. Presentation отображает их как рабочий день:

`09:00 + 540 минут × currentTurn / maxTurns`

- turn `0` => `09:00`;
- финальный turn => ровно `18:00`;
- отображение времени не создаёт и не расходует действий;
- старый `turn N/max` остаётся внутренним и скрывается из player-facing HUD.

## Оболочка чата

Read-only каналы:
- `НАЧАЛЬНИК`;
- `ОТДЕЛ`.

Narrative effects:
- `BossChatMessage`;
- `DepartmentChatMessage`;
- `Toast`.

Входящее сообщение:
1. добавляется в историю канала;
2. увеличивает unread, если канал сейчас не открыт;
3. создаёт временный toast;
4. клик по toast открывает нужный канал;
5. взаимодействия чата никогда не расходуют gameplay-turn.

Ввод текста игроком не входит в релизный объём.

## Presentation протагониста

`ProtagonistLine` — настоящий endpoint NarrativeLayer, но остаётся независимым от конкретного арта.

Поддерживаются:
- text;
- mood `Normal / Tired / Alarmed / Psychotic`;
- lifetime `Timed / OnClick / TimedOrClick`.

Placeholder bubble владеет собственным raycast. Dismiss-click поглощается UI, завершает narrative ticket и не вызывает взаимодействие с worksheet/экономикой ходов.

Поздний pixel-art pass должен заменять только визуал аватара/bubble, а не контракт NarrativeLayer.

## Временный мост к legacy UI

Старый report/sidebar код всё ещё содержит проверенные gameplay callbacks. `PrototypeLegacyRailAdapter` вписывает старую систему координат в новый rail масштабированием transform, а не перестройкой каждой кнопки.

Это сознательный джемовый техдолг: сейчас сохранить рабочие взаимодействия, а внутренности скина/layout менять только если останется время.

## Первый Play Mode smoke

Проверить:
1. проект компилируется;
2. Gameplay принимает все прежние взаимодействия листа/формул;
3. экран использует production-композицию 1600×900;
4. worksheet полностью виден и кликабелен;
5. report/sidebar buttons работают;
6. часы стартуют с `09:00` и двигаются после действий;
7. raw turn label скрыт;
8. Narrative self-test в итоге выдаёт `PASS`;
9. тестовый `ProtagonistLine` появляется в bubble и закрывается по lifetime или клику;
10. UI-клик не тратит gameplay-turn, если это не существующий игровой control.

Визуальная красота **не** является критерием приёмки этого слоя. Важны геометрия, читаемость и целостность взаимодействий.
