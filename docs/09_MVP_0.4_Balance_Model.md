# EXEL HELL — MVP 0.4 balance model

The spreadsheet is the main working model; this note records the assumptions used for the next smoke-tests.

## Current first-order model

- `C` = heuristic Base Cost without anomaly interference.
- `H` = approximate first threat horizon.
- current approximation: `H = first spawn delay + preferred spawn distance = 3 + 2 = 5`.
- `M = H - C`.

Bands:
- `M >= 3` — SAFE;
- `M = 1..2` — LIGHT;
- `M = 0` — EDGE;
- `M = -1..-2` — PRESSURE;
- `M <= -3` — OVERLOAD.

This is a smoke-test filter, not an exact solver. Real difficulty depends on target geometry, #REF! route, destroyed cells and the order in which data stop being needed.

## Updated heuristic solo costs

- ST Salary Total: 2;
- OT Overtime Total: 2;
- BT Bonus Total: 2;
- B5 Bonuses >= 5: 5;
- MS Salary of max-overtime employee: 4;
- LH Salaries where Hours < 40: 4.

B5 is deliberately raised relative to the early paper estimate: smoke-test 06 showed that conditional subset assembly requires several relocation/compression actions in the actual board.

Known shared preparation:
- OT + MS: one Overtime SORT can serve both goals;
- BT + B5: one Bonus SORT can serve both goals under the new non-consuming Report SUM rule.

MS + LH receives an extra overlap estimate because the same Sidorov salary token must be staged/reused after SUM(1) is removed.
