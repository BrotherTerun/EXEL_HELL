# EXEL HELL — MVP 0.4 decisions

This file used to be the MVP 0.4 backlog. The first graybox pass is now resolved and implemented.

## Implemented in MVP 0.4

### SUM(single cell)

Resolved:
- `SUM` requires at least **2 numeric cells**;
- single-cell SUM can no longer replace CUT/PASTE.

Role split remains:
- CUT/PASTE = relocation;
- SUM = aggregation/compression.

### Overlapping report goals

Chosen temporary MVP rule: **Report-target SUM is non-consuming**.

- SUM into a normal worksheet cell consumes its sources;
- SUM directly into a Report Cell writes the numeric answer but leaves source tokens on the worksheet.

Reason: keep overlapping goals without adding COPY / REF / manual input before the core is frozen.

Normal SUBMIT still validates **numeric answer only**.

### Fresh dataset

All numeric values and dependent answers were replaced after repeated MVP 0.3 tests started producing memorized/meta solutions.

New key answers:
- Salary Total = 312;
- Overtime Total = 16;
- Bonus Total = 27;
- Bonuses >= 5 = 21;
- Salary of max-overtime employee = 71;
- Salaries where Hours < 40 = 200.

### Graybox usability

Implemented:
- UI version now says MVP 0.4;
- Report Cells have a persistent green treatment;
- selection is visible over Corrupted and Destroyed cells via a stronger outline;
- initial Canvas layout is forced before the first stable render to fix the misleading spawn telegraph position;
- spawn diagnostics remain available in Console.

## Deliberately unchanged

For this pass do **not** change:
- DELETE rules;
- SORT AI / ordering semantics;
- #REF! movement AI;
- outbreak cadence / speed;
- numeric-only boss validation.

## Still under observation

### DELETE

MVP 0.3 smoke-test 10 finally produced a natural DELETE use under high spatial pressure. Keep it until more tests show whether this was exceptional or repeatable.

### Row / Record SORT

Repeated smoke-tests rarely used RecordKey SORT. Keep it for the next semantic-goal tests; cut it only if it remains dead after fresh-data runs.

### Column SORT opening tax

Repeated tests show a strong pattern: safe early turns often begin with automatic FieldKey SORTs. The same SORT becomes interesting once #REF! damages geometry.

Do not rework SORT yet. First verify whether MVP 0.4 reaches dangerous geometry early enough and consistently enough.

## Next verdict

Run the five smoke-tests from the updated balance workbook. If at least some EDGE/PRESSURE cases reproduce the restructuring behaviour seen in smoke-tests 09–10 without a broken goal combination, freeze the core and move to production/UI/narrative/juice.
