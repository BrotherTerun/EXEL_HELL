# HOOK
EXCEL HELL = тактический пазл внутри таблицы.

Бухгалтер пытается закончить отчёт внутри псевдо-Excel, пока таблица постепенно сходит с ума. Формулы превращаются в правила физики таблицы, ошибки — в угрозы, сама структура документа начинает сопротивляться игроку.

Ключевой принцип: **знакомые правила и инструменты офисного ПО должны становиться буквальными игровыми правилами**. Игрок не получает абстрактные «способности» — он учится использовать реальный смысл `SUM`, `CUT`, `PASTE`, `DELETE`, ссылок, строк, столбцов и формул неожиданным способом.

## Core Verb
Выбирать диапазоны клеток и применять к ним формулы/операции. Одни и те же офисные инструменты используются одновременно и для выполнения отчёта, и для борьбы с аномалиями.

# Core-loop
Рабочая задача → оценить состояние таблицы и заранее показанные угрозы → выбрать приоритет: продвинуть отчёт или спасти данные → применить формулу/операцию → потратить игровое время → система исполняет запланированные события → адаптироваться → подготовить и отправить отчёт до конца рабочего дня.

Для MVP этот цикл временно проверяется пошагово:

`Generate Intent → показать угрозу → Player Action → Resolve Action → Resolve Anomaly → Age Corruption → Generate Next Intent → Check Win/Lose`

## Время — целевая модель полной игры
Полная версия работает **в реальном времени**, а не по схеме «одно действие = один игровой час».

- Рабочий день: ориентировочно `09:00–18:00`.
- Ориентир масштаба: **1 игровой час ≈ 1 минута реального времени**.
- Время идёт, пока игрок думает и работает.
- Операции могут занимать разное количество времени.
- Аномалии и системные события имеют время исполнения.
- Игрок заранее видит ближайшую угрозу и момент её исполнения.

Время — отдельный ресурс давления. Игрок должен решать не только **что** сделать, но и **что он успеет сделать до следующего события**.

Фоновый звук тикающих часов используется как часть механики ощущения времени:
- нейтральный ритм в начале;
- сигналы прошедших игровых часов;
- усиление давления ближе к дедлайну;
- позднее — нарушение ритма, пропущенные/лишние тики и рассинхрон с интерфейсом как часть психоза.

**MVP остаётся пошаговым только для быстрой проверки core.** Технически аномалии не должны быть жёстко привязаны к `EndTurn()`: в полной версии эту роль принимает `GameClock + Scheduler`.

# Угрозы и telegraphing
Аномалии не должны ощущаться случайным пожаром.

Перед исполнением опасного действия игра показывает **Anomaly Intent**: что именно произойдёт и когда.

Для `#REF!` игрок заранее видит клетку следующего распространения и стадию уже заражённых клеток.

В полной версии тот же принцип применяется к будущим аномалиям: сдвигу строки/столбца, перестановке данных, изменению размеров области и другим нарушениям таблицы.

Игрок решает **известную тактическую задачу ограниченными средствами**, а не реагирует на случайный результат постфактум.

## WOW-моменты
- `SUM` впервые буквально стягивает/объединяет содержимое нескольких клеток;
- `#REF!` начинает физически пожирать соседние клетки;
- целый столбец пытается сбежать за край окна;
- знакомая spreadsheet-команда неожиданно становится способом решить пространственную задачу;
- начальник продолжает писать «отчёт будет сегодня?» в момент полного распада таблицы;
- позднее сам интерфейс перестаёт быть рамкой игры и становится частью игрового пространства.

# Общее направление визуала
Игра должна сначала выглядеть как убедительно скучная корпоративная spreadsheet-программа. Психоз возникает не из хоррор-декораций, а из постепенного нарушения знакомых правил интерфейса: значения меняются без команды игрока, границы клеток съезжают, выделение начинает вести себя неправильно, строки и столбцы физически деформируются, системные сообщения вторгаются в рабочую область.

Базовый интерфейс остаётся максимально читаемым: светлая таблица, нейтральные серо-белые панели, один спокойный акцентный цвет, моноширинный шрифт для формул и значений. Чем дальше заходит психоз, тем сильнее UI нарушает собственную геометрию, но важная игровая информация всегда остаётся различимой.

# Основные механики
- **Работа с таблицей.** Игрок выбирает одиночные клетки или прямоугольные диапазоны и применяет к ним офисные операции.
- **Формулы как физические правила.** Семантика команды напрямую определяет игровой эффект. Это главный дизайн-принцип игры.
- **Telegraphed Threat.** Игрок заранее видит следующую цель/действие аномалии и в полной версии — время исполнения.
- **Работа над отчётом.** Игрок вычисляет и сохраняет обязательные показатели.
- **Спасение данных.** `CUT → Clipboard → PASTE` позволяет эвакуировать нужные значения, но требует времени.
- **Локализация заражения.** `DELETE` позволяет пожертвовать клеткой/данными, чтобы остановить или перенаправить распространение ошибки.
- **Преобразование данных.** `SUM` одновременно выполняет настоящую рабочую задачу и меняет состояние игрового поля.
- **Real-time pressure.** Рабочий день идёт независимо от решений игрока; MVP временно заменяет время ходами.
- **Timed execution.** Отдельные действия и события могут иметь собственную длительность.
- **Ранняя отправка.** Игрок может нажать `SUBMIT` до дедлайна, приняв риск ошибки.
- **Эскалация интерфейса.** По мере прохождения элементы spreadsheet UI сами становятся игровыми сущностями и начинают нарушать ожидаемое поведение.

# MVP
Фиксируем MVP как проверку тактического core, а не целевой временной модели:

- поле **10×10**;
- часть клеток содержит исходные числа;
- **3 итоговых показателя отчёта**;
- временно **15 ходов**;
- подтверждённое действие = 1 ход;
- после действия исполняется заранее показанный `Anomaly Intent`;
- единственная аномалия — `#REF!`;
- заражение: `Normal → #REF! → Destroyed`;
- `#REF!` заранее показывает следующую цель;
- победа: правильно заполнить обязательные показатели и нажать **SUBMIT**;
- поражение: дедлайн либо потеря критически необходимых данных;
- курсор и выделение диапазонов;
- `SUM`, `CUT`, `PASTE`, `DELETE`;
- одна основная задача — заполнить/сохранить необходимую часть отчёта;
- **никакого настоящего Excel parser'а**;
- один авторский тестовый сценарий.

`SORT`, другие формулы, другие аномалии, real-time clock, сюжет, звук и визуальный polish добавляются после проверки core.

# Референсы
## Baba Is You — главный концептуальный gameplay-reference
Берём прежде всего **ощущение от взаимодействия с правилами**.

В *Baba Is You* привычное правило перестаёт быть невидимой системной условностью и становится частью пространства, которой игрок может манипулировать. EXCEL HELL должен добиваться похожего эффекта через язык spreadsheet:

> «Я знаю, что означает эта команда в Excel. Теперь я понял, как использовать её буквальный смысл как игровой инструмент».

Поэтому новые механики желательно выводить из уже существующей семантики Excel/офисных инструментов, а не придумывать поверх сеттинга абстрактные способности.

## Into the Breach
- заранее показанные действия угроз;
- детерминированная тактическая задача;
- маленькое поле и ограниченный набор средств;
- защита критически важных объектов/данных.

## Microsoft Excel / Google Sheets
- базовый UX: Cell, Range, active cell, row/column headers, drag-selection, clipboard;
- источник новых игровых правил, операций и аномалий;
- не изобретаем управление таблицей заново без необходимости.

## Papers, Please
- работа сама является core gameplay;
- один стационарный рабочий интерфейс;
- дедлайн и принятие решений через обычные рабочие действия.

## Hypnospace Outlaw
- визуальная убедительность фиктивной компьютерной среды;
- ощущение настоящего приложения/ОС, а не обычной игры со скином рабочего стола.

## Progressbar95 / There Is No Game / Windowkill
- элементы UI превращаются в игровые объекты;
- нарушение ожиданий от интерфейса;
- поздняя эскалация, где рамки окна, панели, строки и столбцы перестают быть неприкосновенной частью HUD.
