# EXEL HELL — Formula Cells 2.0 multidimensional balance model

Status: authoring/smoke-test model for `experiment/formula-cells` after transition to `Drag=MOVE`, `Shift+Drag=SELECT` and movable FormulaCell properties.

The model is not an exact solver. Its job is to reject brittle layouts before playtest and to separate four different things that can otherwise look like the same «difficulty»:

1. useful report workload;
2. spatial manipulation workload;
3. FormulaCell handling tax;
4. anomaly pressure.

Action costs are defined in `04_Typical_Action_Sequences.md`.

---

## 1. Core action cost

### `C0` — legal base action cost

Minimum number of turn-spending actions required to satisfy all report goals with `#REF!` disabled.

Free:
- click;
- `Shift+Drag` selection;
- changing selection;
- reading Formula Bar;
- SUBMIT/checking an already assembled report.

Costs 1 turn:
- successful token MOVE;
- successful range MOVE;
- successful empty FormulaCell MOVE;
- key drop into `=SORT()`;
- numeric-range drop into `=SUM()`;
- DELETE/quarantine.

`C0` must come from an explicit legal sequence on the exact authored layout.

If no legal sequence exists under destructive SUM, ReportCell persistence and current FormulaCell rules:

`C0 = ∞`

The level is invalid regardless of turn budget.

### `C_sem` — semantic lower bound

Minimum useful computation/manipulation actions needed for the goal set assuming favorable geometry and enough formula inventory.

Examples from current goal vocabulary:
- `SalaryTotal`: `C_sem = 2`;
- `Bonus >= 5`: `C_sem = 4`;
- `SalaryOfMaxOvertime`: `C_sem = 3`;
- `SalaryForHoursBelowForty`: `C_sem = 5`;
- `SalaryTotal + Bonus >= 5`: `C_sem = 6`;
- `MaxOvertimeSalary + LowHoursSalary`: `C_sem = 7 + G_rect`;
- `LowHoursSalary + OvertimeTotal + BonusTotal`: `C_sem = 9`.

`G_rect` is unavoidable extra geometry cost required to make a valid rectangular SUM selection when one operand already lives in a persistent ReportCell.

### `C_spatial`

Extra actions above the semantic lower bound caused by meaningful spatial conditions:

`C_spatial = C0 - C_sem - C_formula_tax`

Examples:
- moving a blocker out of an intended spill area;
- choosing to relocate a formula to a safer/useful coordinate;
- moving filtered values because their current positions prevent a valid range;
- staging an aggregate because later geometry needs it elsewhere.

This is the kind of extra cost Formula Cells 2.0 is supposed to create.

## 2. Formula Handling Load

Movable formulas are useful only if their movement creates choices. Repeatedly extracting occupants merely to reuse one scarce formula is maintenance tax.

For a legal base sequence record:

### `F_act`

Total number of useful formula activations (`SUM` + `SORT`).

### `F_move`

Number of MOVE actions that relocate an **empty FormulaCell**.

These are potentially meaningful spatial actions.

### `F_extract`

Number of MOVE actions whose primary purpose is to remove an occupant from a FormulaCell so that the formula can be reused.

Examples:
- moving a completed SUM aggregate directly into its final ReportCell counts as both useful delivery and extraction;
- moving a SORT key to an otherwise irrelevant parking cell only to free SORT counts as pure handling tax.

### `F_delivery`

Number of occupant extractions that simultaneously achieve another required objective: final report delivery, necessary staging, or meaningful repositioning of the token.

### Pure formula tax

`F_tax = max(0, F_extract - F_delivery)`

### Formula Handling Load

`FHL = (F_tax + 0.5*F_move) / max(1, C0)`

Empty-formula movement is weighted at 0.5 rather than 1 because it is the new spatial mechanic we want to exercise; it becomes suspicious only when it consumes a large fraction of the sequence.

Initial bands:
- `<0.10` — light infrastructure handling;
- `0.10..0.20` — noticeable but acceptable;
- `0.20..0.30` — formula management is competing with the puzzle;
- `>0.30` — likely maintenance tax; redesign formula inventory/layout.

Hard authoring warning:

> if scarcity of FormulaCells raises `C0` by more than ~35% above `C_sem` without creating at least one real placement choice, increase formula inventory or redesign.

This rule is motivated by the current lower-bound sensitivity:

| Goal set | enough formulas | 1 SORT | 1 workspace-SUM | 1 SORT + 1 workspace-SUM |
|---|---:|---:|---:|---:|
| SalaryTotal + Bonus >= 5 | 6 | 7 | 8 | 9 |
| MaxOT Salary + LowHours Salary | 7+G | 9+G | 8+G | 10+G |
| LowHours Salary + OT Total + Bonus Total | 9 | 12 | 12 | 15 |

A 9-action semantic puzzle becoming a 15-action formula-maintenance puzzle is not considered added depth.

## 3. Formula placement pressure

Fixed `F_slots` is obsolete because FormulaCells can move.

For each formula instance `f` define:

### `P_f`

Number of currently legal/useful coordinates from which the next required activation of `f` can succeed.

A coordinate is useful only if:
- the FormulaCell may legally occupy it;
- required SORT spill fits, if applicable;
- required SUM/report geometry remains achievable;
- placement does not immediately invalidate another required operation.

### Placement Choice Index

For every activation that requires/preferably benefits from formula relocation, record the number of genuinely viable positions `P_i`.

`PCI = mean(min(P_i, 3) / 3)`

Interpretation:
- `0..0.25` — effectively predetermined placement;
- `0.25..0.50` — limited choice;
- `0.50..0.75` — healthy spatial alternatives;
- `>0.75` — many alternatives; verify that position actually matters rather than being cosmetic.

A movable formula with `P_i = 1` is functionally still a fixed formula plus an extra MOVE tax.

---

## 4. SORT spill geometry

SORT direction remains intrinsic:
- FieldKey -> down;
- RecordKey -> right.

Because SORT itself can relocate, pressure is measured over candidate placements instead of one authored lane.

For required SORT activation `j`:
- `L_j` — required spill length;
- `P_j` — viable formula placements;
- for each placement `p`, `Block_jp` — minimum token MOVE/DELETE actions required before spill succeeds.

Best immediate spill cost:

`SC_j = min_p(Block_jp)`

Alternative count:

`Alt_j = count(p where Block_jp <= SC_j + 1)`

Normalized spill pressure:

`SP_j = min(1, SC_j / max(1, L_j))`

Level:

`SP = mean(SP_j)`

`SA = mean(min(Alt_j,3)/3)`

`SP` measures obstruction; `SA` measures whether the player actually has meaningful placement alternatives.

## 5. MOVE / workspace pressure

CUT/PASTE workspace pressure is obsolete. MOVE needs destination space but no persistent clipboard staging state.

Define:

### `M_filter`

Number of token/range MOVE actions required by the base sequence for filtering, clearing, evacuation or geometry repair.

### `W_free`

Initially usable empty ordinary cells that may accept moved tokens without occupying report/formula infrastructure or mandatory future spill cells.

### `W_peak`

Maximum number of simultaneously parked/staged tokens required by the base sequence.

Workspace pressure:

`WP = W_peak / max(1, W_free)`

Initial bands:
- `<0.10` — spacious;
- `0.10..0.25` — normal;
- `0.25..0.40` — constrained;
- `>0.40` — staging scarcity risks dominating.

Because range MOVE can relocate several tokens in one action, count **simultaneous occupied destinations**, not number of MOVE actions.

## 6. Goal dependency and ReportCell persistence

For every goal `g`, let `S_g` be its raw/source token IDs.

For goal pair `(a,b)`:

`J_ab = |S_a ∩ S_b| / |S_a ∪ S_b|`

Classify:
- `independent`;
- `shared-prep`;
- `ordered`;
- `report-mediated`;
- `hard-conflict`.

`report-mediated` means a token can first satisfy one ReportCell and later be read as a persistent operand by another formula without COPY.

Define:

`DI = mean(J_ab)`

`OC` = number of mandatory ordering constraints.

`RC` = number of report-mediated dependency edges.

Hard-conflict -> `C0 = ∞`.

Important: ReportCell persistence does **not** remove geometry constraints. If the persistent operand and remaining numeric tokens cannot form a valid rectangular SUM selection, the necessary MOVE cost belongs in `G_rect/C_spatial`.

## 7. Critical entities and lifetime

Critical entity set `E` may contain:
- raw data token;
- key token;
- intermediate/final aggregate;
- occupied FormulaCell containing a critical token;
- empty FormulaCell that must still be usable/movable later;
- critical candidate placement/spill region.

For each `e`:

### `U_e`

Last base-plan action index at which the entity must remain usable.

Movable formulas change interpretation: a **coordinate** is critical only while a required placement/region is needed; the Formula property itself may survive by being moved elsewhere.

---

## 8. Threat arrival and mobility

Earliest plausible anomaly contact:

`T_e = F + P_e`

where:
- `F` = first outbreak delay in actions;
- `P_e = D_e + G_e`;
- `D_e` = route/contact distance estimate;
- `G_e` = geometry correction.

Direct outbreak eligibility remains:

`O_e = 1` if `e`/its required position can be directly selected as an outbreak cell before use.

### Mobility recovery

Formula mobility changes loss severity.

An empty threatened FormulaCell usually has finite recovery cost if it can be moved before corruption:

`K_move_formula = 1`

An occupied FormulaCell normally requires:
- MOVE occupant out = 1;
- MOVE formula = 1;

so pre-emptive evacuation can cost up to 2 actions.

If no legal destination for the formula exists, mobility does not help.

---

## 9. Slack / exposure

`S_e = T_e - U_e`

Interpretation:
- `>=3` comfortable;
- `1..2` manageable pressure;
- `0` decision boundary;
- `-1..-2` forced reaction likely;
- `<=-3` overload candidate.

Level:

`S_min = min(S_e)`

`Q = count(S_e <= 1) / |E|`

Exposure bands remain:
- `<0.20` low;
- `0.20..0.40` light;
- `0.40..0.65` strong;
- `>0.65` systemic.

---

## 10. Recovery reserve

`B` — turn budget.

`R = B - C0`

Suggested Formula Cells 2.0 bands:
- `R >= 5` generous;
- `R = 3..4` normal;
- `R = 2` tight;
- `R <= 1` brittle.

The bands are one action lower than the previous model because MOVE compresses common defensive CUT+PASTE reactions from 2 turns to 1.

---

## 11. Anomaly cadence

Let:
- `F` first outbreak delay;
- `A` active-outbreak parallel delay;
- `Resp` respawn delay;
- `C0` base cost.

Approximate outbreak opportunities during optimal play:

`N_A = 0`, if `C0 < F`.

Otherwise:

`N_A = 1 + floor((C0 - F) / max(1,A))`

Normalize:

`AP = min(1, N_A / 3)`

MOVE shortening `C0` means old anomaly timings cannot be reused blindly: the same `FirstOutbreakTurn` now occurs later relative to puzzle progress.

---

## 12. Loss severity

For each critical entity:

`K_e` = minimum extra actions needed after its loss/threat to restore a legal plan.

Examples under FC2:
- threatened movable raw token: often `K=1` pre-emptive MOVE;
- intermediate aggregate whose sources survive: recomputation cost;
- empty formula threatened but movable: often `K=1` if a viable position exists;
- occupied formula + important occupant: often `K=2` to evacuate both layers;
- destroyed irreplaceable raw token: `K=∞`;
- formula destroyed after no alternate instance remains: `K=∞`.

Normalize finite severity:

`KS = mean(min(K_e,4)/4)`

Any `K_e=∞` with `S_e<=1` -> **catastrophic-exposure candidate**.

---

## 13. Revised Puzzle Load

Old `FL` is removed. Formula scarcity is now represented by `FHL`; formula mobility/choice by `PCI/SA`.

Normalize:

`C_n = min(1, C0 / 12)`

`M_n = min(1, M_filter / 5)`

Spatial choice contribution should reward meaningful spatial requirements, not punish alternatives. Therefore `PCI` is used as a diagnostic/gate, not directly as difficulty weight.

Revised:

`PL = 100 * (0.45*C_n + 0.15*SP + 0.15*M_n + 0.10*DI + 0.10*WP + 0.05*FHL)`

Interpretation:
- `0..25` tutorial/light;
- `26..45` normal;
- `46..65` involved;
- `66+` high load.

### Formula design gate

A level is not accepted as a good Formula Cells 2.0 spatial puzzle solely because `PL` is high.

Require for any level whose identity relies on movable formulas:
- at least one formula relocation with `P_i >= 2`, **or** a clearly meaningful choice to leave formula in place;
- `FHL <= 0.25` preferred;
- formula scarcity must not add >35% to `C_sem` without compensating spatial choice.

This gate is deliberately separate from PL.

---

## 14. Revised Anomaly Threat

Slack normalization:

`SN = clamp((2 - S_min)/5, 0, 1)`

Direct-spawn ratio:

`OR = count(O_e=1)/|E|`

`AT = 100 * (0.30*SN + 0.25*Q + 0.15*AP + 0.15*KS + 0.15*OR)`

Bands unchanged:
- `0..20` decorative;
- `21..40` light pressure;
- `41..60` active tactical pressure;
- `61..80` severe;
- `81+` chaotic/catastrophic.

Formula mobility is reflected indirectly through lower finite `K_e`; do not subtract a separate mobility bonus and double-count it.

---

## 15. Combined score

`D = 0.55*PL + 0.45*AT`

Keep `(PL,AT)` visible; `D` is only a summary.

Also report the FC2-specific diagnostics:

`(C_sem, C0, FHL, PCI, SA)`

These tell us whether Formula Cells are creating spatial choices or merely inflating workload.

## 17. Provisional target curve

Do not reuse old FC1 target values unchanged. MOVE reduces action tax and movable formulas should create choices before anomaly pressure is added.

| Role | Target PL | Target AT | FC2-specific requirement |
|---|---:|---:|---|
| 1. Interaction tutorial | 10–25 | 0 | Teach MOVE/SELECT/drop; no forced formula relocation |
| 2. Formula placement test | 20–35 | 0–15 | At least 2 viable positions for one formula; `FHL < .15` |
| 3. Formula + REF test | 25–40 | 20–35 | REF changes preferred formula/data placement, not solvability |
| 4. Dependency test | 35–50 | 30–45 | report-mediated or ordered goals; `FHL <= .20` |
| 5. Pressure/final test | 40–55 | 40–55 | multiple goals, finite recovery; avoid catastrophic single-point failure |

These bands are hypotheses until the first FC2 smoke tests produce observed action counts.

## 18. Immediate implications before rebuilding levels

1. **Do not optimize for minimum formula count.** Minimum inventory is not automatically better design.
2. `1 SORT + 1 SUM` is acceptable only when their reuse itself creates useful placement decisions. It is not a default target.
3. A report-SUM saves one delivery MOVE but pins that SUM behind the completed report occupant; this is a real inventory trade-off.
4. Workspace-SUM is reusable because moving its aggregate out both delivers/stages the result and frees the formula.
5. Formula relocation is valuable only when there are at least two plausible destinations with different consequences.
6. MOVE compression means `FirstOutbreakTurn`, `ActiveOutbreakDelay` and turn budgets must all be recalibrated after layouts are rebuilt.
7. The next level pass should be evaluated first with `#REF!` disabled to verify that movable formulas actually add spatial choice. Only then tune anomaly pressure.
