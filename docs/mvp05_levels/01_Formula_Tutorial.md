## Стартовое поле

Обозначения:
- `K:SAL`, `K:OT`, `K:H`, `K:B` — ключи параметров;
- `R:*` — RecordKey;
- `Σ` — `=SUM()`;
- `S↓` — `=SORT()` с spill вниз;
- `REP` — заголовок отчёта;
- `·` — пустое поле.

Formula cells:
- `B2 = SORT`, fixed direction down;
- `E2 = SORT`, fixed direction down;

- `H3 = SUM`, report target Overtime Total.

## Минимальная легальная последовательность

1. Выделить `K:SAL` → активировать `B2 =SORT()`.
2. Выделить `B3:B7` → активировать `H2 =SUM()` → `=SUM(318)`.
3. Выделить `K:OT` → активировать `E2 =SORT()`.
4. Выделить `E3:E7` → активировать `H3 =SUM()` → `=SUM(15)`.

`C0 = 4`.

Никакой обязательный CUT/PASTE не требуется. Это проверяет главный тезис MVP 0.5: переход к formula cells не увеличивает стоимость простой цепочки `SORT + SUM`.

## Функция balance model

Используется модель из `12_MVP_0.5_Balance_Model.md`:

`PL = 100*(0.45*C_n + 0.20*FL + 0.15*SP + 0.10*DI + 0.10*WP)`

`AT = 100*(0.30*SN + 0.25*Q + 0.15*AP + 0.15*KS + 0.15*OR)`

`D = 0.55*PL + 0.45*AT`

### Подстановка

| Метрика | Значение | Причина |
|---|---:|---|
| `C0` | 4 | две независимые цепочки SORT+SUM |
| `B` | 10 | tutorial reserve |
| `R=B-C0` | 6 | большой запас |
| `F_need` | 4 | 2 SORT + 2 SUM |
| `F_reuse` | 0 | отдельные formula cells |
| `FL` | 0 | нет reuse |
| `SP` | 0 | обе spill lanes свободны |
| `DI` | 0 | Salary и Overtime не пересекаются |
| `OC` | 0 | порядок целей свободный |
| `WP` | 0 | staging не нужен |
| `N_A/AP` | 0 / 0 | REF выключен |

`C_n = 4/12 = 0.333`.

`PL ≈ 15.0`.

Так как аномалия выключена: `AT = 0`.

`D ≈ 8.2`.

## Ожидаемый тест

Проверяем только:
- понимает ли игрок, что formula cell активируется выделением аргумента;
- считывает ли `=SORT(key)` / `=SUM(n)` как состояние поля;
- понимает ли направление spill по расположению формулы;
- не ощущается ли новый loop длиннее/медленнее старого при той же цене в ходах.
