# EXEL HELL — документация

Документация ветки `jam/final-build` разделена по языку и статусу.

## Структура

- [`ru/`](ru/) — русскоязычная документация: переводы актуальных англоязычных спецификаций и документы, изначально написанные на русском.
- [`en/`](en/) — английские оригиналы актуальных/самостоятельных документов.
- [`legacy/`](legacy/) — явно устаревшие документы, заменённые более новой версией, а также старые индексы, которые противоречат более свежему состоянию документации.
- [`balance/`](balance/) — общие языконезависимые CSV/XLSX-артефакты баланса.
- [`images/`](images/) — общие изображения документации.

## Правило версий

Если у документа существует более новая версия `vN`, рабочей считается самая поздняя версия, а предыдущая помещается в `legacy/`.

Документы без версионного аналога не объявляются устаревшими автоматически: они сохраняются как самостоятельные материалы проекта.

## Важно о временных контрольных точках

Некоторые самостоятельные документы фиксируют состояние проекта на конкретный момент джема и могут описывать планы, которые позднее были урезаны или изменены. Для фактического runtime-состояния всегда сверяйтесь с кодом `jam/final-build` и наиболее поздними релизными материалами.

Финальная игровая прогрессия релизной сборки — **L1–L4**; старые заметки, где планировался L5, сохранены только там, где они являются самостоятельной историей проектирования, либо перенесены в `legacy`, если были прямо заменены более свежим документом.
