# Типовые цепочки действий

Считаем только действия, которые тратят ход. Выделение диапазона и указание целевой клетки — бесплатно.

## Базовые цепочки

1. **Прямая агрегация — 1 ход**  
   `Диапазон → SUM → result cell`

2. **Сборка параметра + агрегация — 2 хода**  
   `FieldKey → SORT → диапазон → SUM → result cell`

3. **Сборка записи + агрегация — 2 хода**  
   `RecordKey → SORT → диапазон → SUM → result cell`

4. **Расчистить spill + SORT + SUM — 4 хода**  
   `мешающий token → CUT → свободная cell → PASTE → key → SORT → диапазон → SUM`

5. **Карантин + SORT + SUM — 3 хода**  
   `#REF! → DELETE → key → SORT → диапазон → SUM`

6. **Эвакуация нужного значения + SORT + SUM — 4 хода**  
   `required token → CUT → safe cell → PASTE → key → SORT → диапазон → SUM`

7. **Две независимые агрегации — 2 хода**  
   `range A → SUM → result A → range B → SUM → result B`

8. **Две сборки + две агрегации — 4 хода**  
   `key A → SORT → SUM → key B → SORT → SUM`

9. **Сборка → перестройка другой проекции → агрегация — 3 хода**  
   `RecordKey → SORT → FieldKey → SORT → диапазон → SUM`
   
   Используется, когда игрок сначала собирает запись, чтобы понять/освободить данные, а затем собирает нужный параметр. Вторая сортировка разрушает первую пространственную структуру, но семантика токенов сохраняется.

10. **Спасти результат от Intent — +2 хода к любой цепочке**  
    `готовый/промежуточный token → CUT → safe cell → PASTE`

## Условная сложность отчётной цели

- **L0 — 0 ходов:** нужное значение уже готово и его достаточно перенести/сохранить без игровой операции.
- **L1 — 1–2 хода:** прямая `SUM` или `SORT + SUM`.
- **L2 — 3–4 хода:** требуется дополнительная перестройка, расчистка, эвакуация или карантин.
- **L3 — 5+ ходов:** несколько обязательных преобразований, спасений или конфликтующих проекций.

## Что реально повышает сложность уровня

Сложность уровня не равна простой сумме минимальных ходов целей. Важнее конкуренция цепочек за:

- одни и те же исходные данные;
- свободные клетки и непрерывные области для `SORT`;
- безопасные клетки для промежуточных/итоговых значений;
- время до исполнения `#REF! Intent`;
- необходимость разрушить одну удобную структуру данных, чтобы собрать другую.

Для core-test желательно, чтобы хотя бы одна отчётная цель была **L2**, а `#REF!` вмешивался в её минимальную цепочку и заставлял потратить дополнительное действие или изменить порядок действий.
